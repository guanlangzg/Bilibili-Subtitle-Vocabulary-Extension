## 性能实测

以下均为同条件修改前后对比。Node 基准使用 v24.20.0；存储以隔离适配器替代，保留真实业务模块，不把内存存储的耗时视为真实扩展端到端延迟。

| 场景 | 修改前 | 修改后 | 测量范围 |
| --- | ---: | ---: | --- |
| 单次曝光 `recordHit`，5,000 条学习记录 | 4.722 ms | 0.084 ms | 200 次调用均值；真实词库模块，合成记录，后台消息桩 |
| 单次曝光的后台响应，2,000 词 / 1,000 事件 | 2,233,188 字节 | 37 字节 | 5 次响应中位数；持久化仍完整执行 |
| 五页同步，1,000 条已有事件 + 500 条新增事件 | 231.07 ms | 68.40 ms | 同一进程分别执行 HEAD/当前同步模块，预热后 3 次中位数 |
| 同一五页同步的写入量 | 3,922,445 字节 / 6 次写入 | 883,905 字节 / 2 次写入 | 包含学习数据及同步配置写入 |
| 弹窗学习概览，5,000 记录 / 8 条队列 | 90.76 ms | 27.17 ms | 真实 TS 模块经 transpile + VM 执行，5 次中位数，包含存储桩复制 |
| 弹窗学习概览，30,000 记录 / 8 条队列 | 552.01 ms | 196.73 ms | 逐词归一化次数由 30,000 降至 8 |
| 浏览器字幕候选探测，单条真实 DOM 字幕 | 0.0677 ms / 40 次 closest | 0.0457 ms / 2 次 closest | 同页加载 HEAD/当前解析器，预热后各 300 次，均检测到 1 条字幕 |

主要实现：

1. `vocabulary.js:858` 不再在每次曝光时计算无人消费的摘要；学习记录刷新只更新索引引用，不重建固定词库索引。
2. `background-learning-state.js:398` 曝光响应只返回单词、事件 ID 和可选的重复标记，不再回传整份投影。
3. `background-learning-sync.js:137` 多页拉取后只导入一次，避免逐页重做合并、投影和写库。
4. `react-ui/src/lib/storage.ts:962` 只归一化复习队列实际引用的记录；排行扫描时选取前 N 条，排序口径保持一致。
5. `subtitleParser.js:118` 合并祖先排除选择器；没有时间轴文本时，内容脚本跳过第二次全量字幕探测。
6. `learningData.js:23` 将 MD5 轮次常量预先计算；跨端单词 ID 测试和逐词比对保持一致。

排行读取在 30,000 条基准下为 228.30 → 223.40 ms，收益较小，不作为主要性能改善。弹窗虽然只注册一个学习数据订阅，概览和排行仍分别读取存储，没有合并成一次读取。

## 一并修复的真实缺陷

- `contentScript/index.js:600`：停用时使在途翻译失效，初始化在入口与异步步骤后检查停用状态，防止 DOM ready 或异步初始化晚到后重新注册监听器。
- `contentScript/dom-observer.js`：已销毁的动画帧任务不再渲染、恢复文本或继续处理下一项。
- `scripts/danmaku.js:511`：销毁等待播放器的宿主观察者、清理备用定时器和弹幕容器，支持再次挂载。
- `vocabulary.js:408`：索引引用更新使用实际建立索引的 `matchTerms`，修复别名不在释义中时学习状态停留在旧对象的问题。
- `learningDataSync.js:47`：令牌保持原值验证，拒绝首尾空白。
- `background-learning-sync.js:32`：更换服务器或令牌时重置拉取游标及旧同步结果；同一连接不让页面旧快照覆盖最新同步状态。
- `background-learning-sync.js:202`：只保存已经成功拉取的游标，上传返回的全局游标不再跳过其他设备新增但尚未拉取的事件。到达分页上限时向界面返回 `hasMore`。
- `react-ui/src/components/overlay-entry.tsx:385`：隐藏态恢复按钮包含主题容器；最近词汇显示中文学习状态，移除后台从未提供的释义字段。

## 保留的审查发现

这些条目需要单独的行为设计或更大范围验证，本轮没有修改：

1. **大日志下的后台写入仍会增长**：`background-learning-data.js:279`、`background-learning-state.js:315` 每次学习变更仍基于完整事实日志生成投影并写入，事实日志没有裁剪上限。大量历史记录会增加合并与存储成本，最终可能遇到配额；不能直接删除事件，否则会破坏跨端事实合并和幂等性。需要协议层的压缩/归档方案。
2. **同步网络仍占用共享写队列**：`background-message-handler.js:279` 整个同步任务位于共享串行队列内。慢网络期间设置和学习写入会等待。拆分网络阶段与写入阶段必须重新验证游标、并发学习写入和一致性。
3. **已收藏且 mastered 的记录可能无法单独取消收藏**：`background-learning-state.js:654` 用 `saved` 判断收藏，而 `learningState.js:1138` 的移除辅助函数只接受 `status === 'saved'`。导入数据可同时保留收藏事实和掌握状态；这两种判定需要统一。
4. **自定义配置档存在成功提示不准确**：`react-ui/src/components/options-main.tsx:184` 无条件提示创建成功，但 `sharedSettings.js:617` 会拒绝内置 ID、覆盖同 ID 自定义档。名称冲突策略需要明确。
5. **引导保存失败保留已修改草稿**：`react-ui/src/hooks/use-onboarding.ts:54` 先更新草稿再保存，失败时不恢复；需要确定保留编辑还是回滚的交互。
6. **同步“上次错误”尚未持久化接线**：本轮删除了从未被调用的 `recordSyncFailure`。当前错误可在界面本次操作中显示，但不会写入 `lastError`；历史错误展示需要单独接入队列内的持久化行为。
7. **继续测量调度开销**：300 ms 字幕轮询、timeupdate 导航时间轴归一化以及 translator 过期清理仍在原路径运行；本轮只减少确定的重复探测，没有改变轮询策略或时间轴查找语义。

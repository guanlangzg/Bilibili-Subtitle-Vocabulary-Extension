# 插件与 App 学习数据互通协议 v1

本协议用于 Bilibili 字幕词汇插件与 `安卓背单词` App 的本地数据对齐，服务器同步沿用相同的事实记录。插件已接入服务器同步；App 侧接入暂缓。

## 数据边界

- `wordId` 标识一个英文词。同词的学习贡献和共同进度跨词书归并，`bookCodes` 仅记录词书归属。App 既有按词书保存的卡片与复习日志保留。
- `events` 是不可变学习事实：`exposure`、`lookup`、`save`、`unsave`、`suspend`、`resume`、`review`。曝光和查词不算完成复习。
- `baselines` 保存升级前无法还原为逐次记录的历史聚合。每设备、每单词最多一份基线。App 有真实历史日志时转换为事件，对应基线扣除已经转换的次数，避免重复贡献。
- `progress` 是基线和事件的派生结果，不作为导入时覆盖事实的依据。收藏、暂停学习与复习状态分别保存。

## 交换格式

```json
{
  "format": "vocab-learning-data",
  "schemaVersion": 1,
  "exportedAt": 1767225603000,
  "events": [],
  "baselines": []
}
```

单行基线计数及快照的天数、次数采用非负 32 位整数；派生进度及贡献累计采用不超过 JavaScript 安全整数范围的非负整数。

完整的双方共用样例在 `bilibili-vocab-extension/tests/fixtures/learning-data-v1.json`。App 测试资源保留同内容副本。可选字段写作 `null`，不使用空字符串、0 或假复习记录表示未知值；未来版本可增加字段，当前解析器忽略未知字段但拒绝未知 `schemaVersion`。

| 身份与时间 | 约定 |
|---|---|
| 单词规范化 | 首尾去除固定的 ECMAScript 空白集合（U+0009–000D、0020、00A0、1680、2000–200A、2028、2029、202F、205F、3000、FEFF），再按 Unicode 默认规则转小写；不归并词形、内部空格或标点。 |
| `wordId` | `word-` + Java `UUID.nameUUIDFromBytes` 的 UTF-8 MD5 v3 结果，不加 UUID 命名空间。`state` 对应 `word-9ed39e2e-a931-386b-aa98-5a6942ef573e`。 |
| `deviceId` | 每次安装生成并持久化的 UUID v4。交换别端数据不替换本机设备身份。 |
| `eventId` | 新行为生成一次小写 UUID v4，重试和转发原样保留 ID。App 旧日志转换使用基于原日志 ID 的稳定标识。交换端按不透明、区分大小写的字符串处理，禁止改写大小写、前缀或重新生成 ID。 |
| `occurredAt`、`capturedAt`、`exportedAt` | UTC Unix 毫秒、安全整数。 |
| `localDay` | 行为发生时的本地日期 `YYYY-MM-DD`。 |
| `zoneId`、`utcOffsetMinutes` | 原时区及当时偏移；不能按导入设备当前时区改写历史日期。 |
| `source` | `extension` 或 `android`。 |
| `bookCodes` | 去重并按 CET4、CET6、KAOYAN、IELTS、TOEFL 排列。 |

事件附带原始 `rawAction`、可空耗时、上下文和调度信息。正式复习的 `rating` 仅允许 `again`、`hard`、`good`、`easy`。插件旧三档输入映射为 `dontknow → again`、`fuzzy → hard`、`know → good`，原动作继续保留。曝光、收藏等非复习事件的评分和算法参数必须为空。

## 进度与贡献归并

- 按 `eventId` 和 `baselineId` 去重。同 ID 内容一致可重复导入；内容冲突拒绝整包，不覆盖原记录。
- 次数等于所有基线计数加所有去重事件的增量；`contributions.extension`、`contributions.android` 分别统计曝光、查词、复习、收藏次数。
- `firstSeenAt`、`lastSeenAt` 来自曝光、查词与历史基线；`lastReviewedAt` 来自正式复习和基线。
- 收藏与暂停按明确行为的发生时间确定最后动作；同刻按 ID 字典序裁决。旧基线的 `true` 仅作低优先级初始值，`false` 不代表明确取消，任何明确事件都优先于基线。迁移时间不是收藏发生时间。取消收藏不删除过去的收藏贡献。
- 当前调度取最后一次带快照的复习结果，快照包含算法及版本；相同时刻按事件 ID 排序。基线快照按实际 `lastReviewedAt` 排序，而非导入时间。
- 单词不在本机词库时仍保留事实，不丢弃数据。

## 调度兼容边界

共同快照保留 `state`、`dueAt`、`lastReviewedAt`、`scheduledDays`、`reviewCount`、`lapseCount`，以及可空的 FSRS `difficulty`、`stability`、`retrievability`、`targetRetention`。插件原间隔算法使用 `algorithm: extension-interval`、`algorithmVersion: 1`，原系数单独放在 `legacyEaseFactor`、`legacyMasteryScore`。

插件旧调度与 App FSRS 本轮不会被当成同一算法。交换快照保留区别，不从 `masteryScore` 推造 FSRS 参数。合并的贡献与历史是双方共同事实；同时离线复习产生的调度分支尚需未来服务器在选定算法及参数版本后统一排序和重算。最新快照的确定性选择不等于完成了 FSRS 历史重放。

插件在收到 FSRS 快照后产生的浏览器复习反馈仍保存为真实事件，但本轮不会用旧间隔算法改写 FSRS 的到期时间。这类事件标记为待调度；统一算法和服务器处理尚未完成。App 原有今日队列、按词书统计及本地调度仍沿用原逻辑，共同进度通过独立 API 提供，不能将本轮数据协议对齐等同于现有全部界面已使用共同队列。

App 旧日志只有历史 `localDay` 而没有原时区时，转换事件标记 `zoneId: legacy-unknown`。兼容偏移仅用于重现已保存的历史日期，不代表恢复了原时区；无法合法表示的日志保留在原表并记录跳过数量。

## 服务器同步（插件已接入）

同步服务为独立部署的 `vocab-sync`（Node 24 + 内置 SQLite），以宿主端口直接对外提供 HTTP 服务，前面没有反向代理。接口与运维说明随服务目录维护，不在本仓库内。

- 每账号一个 bearer token，服务端只存 SHA-256；插件把令牌保存在 `chrome.storage.local`。
- `POST /v1/push` 按 ID 去重，同 ID 内容冲突整包拒绝（409），本地数据不被改写。
- `GET /v1/pull?since=&limit=` 返回按 `server_seq` 升序的事件与基线；两张表共用序号空间并合并排序。
- 服务端不重算调度、不回灌进度；`/v1/progress` 仅供诊断。
- 插件同步实现为 `learningDataSync.js`（纯协议与校验）+ `background-learning-sync.js`（网络与游标），消息类型 `SYNC_GET_SETTINGS`/`SYNC_SAVE_SETTINGS`/`SYNC_GET_STATUS`/`SYNC_RUN`。
- 同步主机权限来自 `optional_host_permissions`，在选项页保存或同步时按实际服务器地址申请。

## 持久化与后续服务器接入

- 本地行为事件与对应本地状态在同一事务或同一次 storage 写入中保存，失败不报告成功。
- 导入不会再次生成本地行为事件，避免转发回环。
- 未获服务器确认的事实记录不按时间或数量自动裁剪。配额不足应报告写入失败。
- 后续服务器增加账号归属、上传确认和拉取游标；这些是同步元数据，不能改写原始事件 ID、时间与来源。
- 本机设置、提醒时间、主题与布局不混入共同学习进度。

## 接入入口

- 插件：`bilibili-vocab-extension/react-ui/src/lib/learning-data-client.ts` 提供 `exportLearningData()`、`importLearningData(bundle)`、`readLearningDataProgress()`；实际读写统一进入后台队列。导出结果中的 `bundle` 才是协议交换包，`progress` 是附带的派生结果。
- App：`core/domain/.../LearningDataRepository.kt` 提供相同的导入、导出与共同进度观察接口；实现在 `core/database/.../OfflineLearningDataRepository.kt`。现有完整备份的 `learningData` 字段保存协议交换包。
- 插件已在选项页“学习记录同步”提供服务器地址、访问令牌和设备标识配置，以及“检查服务器状态”“立即同步”。同步先拉取合并再上传，游标只在导入成功后前进。
- 不能把原有“导出当前配置”按钮当作学习记录导出：前者导出设置，后者导出学习事实。
- App schema 由 10 升到 11，原表和视图保留，新增事件、基线、共同进度与设备信息四张表。结构验证入口为 `scripts/test/verify-learning-data.py`、`scripts/test/verify-learning-schema.py`；完整 Room 验证仍须在 Android 构建环境运行迁移测试。

## 开源实现依据

- [OpenJDK UUID.nameUUIDFromBytes](https://github.com/openjdk/jdk/blob/master/src/java.base/share/classes/java/util/UUID.java)：核对现有 App 的单词 ID 规则。未复制 OpenJDK 源码。
- [uuidjs/uuid 的 v35 实现](https://github.com/uuidjs/uuid/blob/main/src/v35.ts)（MIT）：标准 UUID v3 会拼接命名空间，因此不能直接替换 App 的 ID 规则；本项目仅实现与现有 API 相同的 MD5 名称标识，并用 Node 标准库校验。
- [java-fsrs Scheduler](https://github.com/open-spaced-repetition/java-fsrs/blob/main/src/main/java/io/github/openspacedrepetition/Scheduler.java) 与 [ts-fsrs](https://github.com/open-spaced-repetition/ts-fsrs)（MIT）：默认权重、fuzz 与时间取整存在差异，本轮保留算法版本及结果快照，避免声称两端默认算法输出一致。

## 验收

两端使用同一份样例验证单词身份、JSON 字段、跨时区日期、贡献总量、跨词书归并、重复导入、冲突拒绝和历史基线。另验证本地写入失败及数据库升级保留旧卡片、旧日志。缺少 Android 编译或设备验证时须单独注明，不能仅凭 JS 测试声明两端完整通过。
